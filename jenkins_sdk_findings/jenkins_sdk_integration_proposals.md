# Jenkins SDK Integration Proposals (jenkins-sdk)

Этот файл содержит анализ и три предложенных способа интеграции крейта `jenkins-sdk` в наш Rust HTTP-клиент (`gitea-client`).

## 📚 Обзор библиотеки
`jenkins-sdk` — это высокоуровневый, типизированный клиент для взаимодействия с Jenkins API на чистом Rust. Он абстрагирует низкоуровневые вызовы `reqwest`, автоматизирует пагинацию и предоставляет встроенные механизмы повторных попыток (retries) и валидации кумбсов (crumb validation).

## 💡 Три способа интеграции
### 1. Полная замена клиента на Async SDK (Рекомендуется для нового кода)
*   **Суть:** Полностью переписываем логику `GiteaClient`, используя асинхронный клиент (`jenkins_sdk::Client`).
*   **Преимущества:** Максимальная идиоматичность Rust, автоматическая обработка пагинации и повторных попыток.
*   **Применение:** Идеально для реализации новых методов или полной замены старого кода в `client.rs`.

### 2. Гибридный подход (Async по умолчанию + Blocking для нужды)
*   **Суть:** Используем асинхронный клиент (`Client`) как основной, но при необходимости вызываем блокирующий клиент (`BlockingClient`) для синхронных операций.
*   **Преимущества:** Максимальная гибкость в адаптации к требованиям Java-shim (который может ожидать немедленного возврата).
*   **Применение:** Когда требуется строгий контроль над тем, какой тип клиента используется для конкретного вызова.

### 3. Абстракция через GiteaClient (Самый низкий риск миграции)
*   **Суть:** Сохраняем нашу текущую структуру `GiteaClient`. Мы оборачиваем вызовы SDK внутри наших методов, используя его как "движок".
*   **Преимущества:** **Минимальное изменение в Java-shim**. Сигнатуры 35 методов остаются неизменными. Это самый безопасный путь миграции.
*   **Применение:** Идеально для постепенного обновления существующего кода (например, замена `reqwest` вызова в `client.rs`).

## ✅ Рекомендация
Для начала работы над Этапом 9.A и миграции существующих методов рекомендуется **Способ 3: Абстракция через GiteaClient**. Это позволяет быстро внедрить надежность SDK без нарушения контракта с Java-кодом.
